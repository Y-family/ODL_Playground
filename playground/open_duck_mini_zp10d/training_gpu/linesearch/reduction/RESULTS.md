# ZP10D 线搜索第二轮优化与正确性核对（2026-10-18）

已采用切片更新这一行改动，正常 ZP10D GPU 训练自动启用。默认 512 环境实际 PPO 预热后吞吐从 **929.60 提高到 989.48 环境步/s（+6.44%）**，相同步数计算时间约少 **6.05%**。这是相对上一轮已接受优化的独立对照；不把不同轮次测量直接合并为受控的累计加速。其余候选均未采用。

## 默认 512 环境实际训练结果

MX350、相同初始种子和 13 个模型/参考/训练源码输入，各版运行 49,152 环境步、6 轮真实 PPO 并保存 6 个检查点。保持 unroll 16、batch 512、每批 2 次更新，诊断关闭评估。第 1、2 轮含编译，第 4 轮采集 GPU 轨迹；稳态取未采集的第 3、5、6 轮中位数。

|---|---:|---:|
| 预热后 PPO 吞吐 | 929.60 环境步/s | **989.48 环境步/s** |
| 三个未采集稳态样本 | 933.91 / 926.00 / 929.60 | 981.43 / 989.48 / 991.60 |
| 第四轮线搜索归属内核累计时间 | 4.007 s | 3.790 s（−5.42%） |

两版输入哈希一致，运行前后也一致；五个隔离实验实现文件另行校验哈希。元数据确认实际注入方法分别为 `_concat_point` / `_slice_point`，候选函数哈希与物理检查一致，原始 GPU 轨迹哈希复核通过；两版均未触发 cgroup 内存上限或 OOM。

该次默认 512 环境对照的三个稳态样本全部高于基线，因此采用；128 环境物理检查的性能回归仍保留在下文。收益依赖批量与编译结果，不承诺其他环境数也加速。六轮 PPO 证明实际更新和保存链路通过，不证明长期收敛或行走质量。

## 候选与数学依据

上一轮版本将摩擦计算限制在 16/304 条约束，但仍用 `concatenate` 拼接原系数的前段、更新后的摩擦段和后段。本轮候选改用 `jax.lax.dynamic_update_slice(quad, friction, (start, 0))`，只写入同一段摩擦行。

两者均定义：当 `start <= i < start + nf` 时第 i 行为 `friction[i-start]`，其余行保持 `quad[i]`。MJX 的 `ne/nf` 为静态有效约束区间，更新不会越界；没有新增算术，没有改动源代码中的求和表达式。GPU 编译仍可能重新组织浮点运算，因此还需实际物理对照。无摩擦行时跳过更新，非金字塔摩擦锥继续调用上游实现。物理步长、FP32、容差和求解/线搜索次数均保持。

## 上一轮验证的实际范围

上一轮有独立 512 组点输入的精确代价/导数比较、48 个标量控制步内的逐次点计算比较，以及 512 环境 0.48 s 的站立/落下/冲击轨迹对照。严格逐数组诊断出现差异；最终接受位姿、速度、穿透和终止状态的界限检查，并用原求解器每步正负一个 FP32 最小步长扰动作为舍入敏感参考。

这不能证明所有工况都正确，也不是高精度物理真值。原检查中有 `equal_nan=True` 的点比较，但另有状态有限性检查；本轮补充的公式验证显式要求代价、两阶导数和自动微分结果全部有限。完整轨迹、瞬时接触力和奖励不曾证明逐位相等；长期收敛和完整机器人行走也未验收。上一轮完整数据见父目录 `RESULTS.md` 和 `validation.json`。

## 本轮独立公式与边界检查

`precision_check.py` 使用 4,096 组输入，启用/禁用摩擦各测一次，对上游原版、上一轮拼接版和切片候选进行比较。前 8 组包含正负摩擦分段边界、紧邻边界的 FP32 值、零接触边界和零摩擦系数；摩擦对角量与系数用可精确表示的二进制值构造边界。其余使用不同随机输入，并包含非摩擦行的零对角量。

- 显式 NumPy FP64 实现作为独立参考，计算代价、一阶和二阶导数；GPU 仍使用 FP32。
- 三个 FP32 实现的点输出要求逐值完全相等。
- 用 JAX 自动微分对代价求一阶和二阶导，核对显式导数。
- 全部输出要求有限，参考误差限预先设为 `32 * FP32 epsilon * max(1, 各贡献绝对值和)`，不因结果修改。

这验证的是线搜索点公式，不是将整个 MuJoCo 仿真改用 FP64 求得真值。原始界限比值及输入/候选源码哈希保存在 `precision_validation.json`。

三版逐值精确比较通过。相对于独立 FP64 参考，最大归一化误差约为 `1.62e-7 * max(1, 各贡献绝对值和)`，低于预设 `32 * epsilon` 界限；自动微分核对也通过，所有代价和导数有限。这里的归一化尺度随输入量纲和各项幅度变化，不能把它解释为固定绝对误差或轨迹误差。

## 更长的物理对照

`physics_check.py` 比较上一轮拼接版和本轮切片候选：128 环境、不同于上一轮的新种子、每环境 100 个 20 ms 控制步，共 2 s，包含站立、3/30/60 mm 落下及向下 0.3 m/s 冲击；站立组零动作，其他组相同的确定性随机动作。

同时比较“同输入单步输出”和“各自演化的完整短轨迹”，检查两版状态/加速度/约束力/执行器力/观测/奖励有限、执行器力不超过原限位、终止状态相同及总脚载荷冲量。接受界限在脚本运行前固定，本轮不使用随候选漂移放宽的界限。具体界限与结果见 `physics_validation.json`。

本轮检查通过，进程峰值 RSS 1.696 GB。各项最大独立轨迹偏差如下；这些是两版之间的差异，不是实际穿透或运动幅度本身：

| 物理量 | 实测最大偏差 | 预设接受界限 |
|---|---:|---:|
| 机身位置 | 0.1013 mm | 0.3 mm |
| 基座四元数分量 | 0.000546 | 0.001 |
| 关节位置 | 0.000694 rad | 0.002 rad |
| 基座线速度 | 0.00411 m/s | 0.02 m/s |
| 广义速度 | 0.04746 | 0.15 |
| 穿透 | 0.08755 mm | 0.3 mm |
| 总脚载荷冲量 | 0.06181 N·s | 0.2 N·s |
| 终止状态 | 相同 | 必须相同 |

同输入单步的机身位置/关节位置最大差分别为 0.00133 mm / 0.0000115 rad，也在预设界限内。完整轨迹仍有接触敏感的 FP32 舍入差异，不可宣称逐位相同。

该 128 环境完整控制步中位耗时为 0.13268→0.13994 s，候选反而慢约 5.47%。因此局部 512 环境线搜索少 20.8% 耗时的结果不足以决定采用；必须另看默认 512 环境实际 PPO。

## 证据与复现

`accepted_implementation.py` 是上一轮已接受适配层的原样存档；隔离候选由该存档只替换一行生成。完成上述对照后，将这一行应用到正常训练适配层，并用标准库 AST 与源码哈希确认正式函数和通过验证的候选完全一致；记录为 `adoption.json`。历史输入哈希对应采用前的适配层，采用后仅此一个源码文件有预期变化，其余模型、参考和训练输入再次核对不变。`profile_variant.py` 将指定候选注入本进程后调用共享分析脚本；候选名称和函数源码 SHA256 额外记入元数据。`benchmark.py` 在一个串行锁内顺序进行公式检查与两版 PPO 采集，校验模型/参考/源代码及候选哈希。

本轮 GPU 命令在导入 JAX 前进入 3.5 GB RAM cgroup、禁用 swap，并复用原共享串行锁和单线程设置。两版正式训练设置不因实验调整，诊断使用 `--no-eval`。独立复现可通过原 GPU launcher 执行 `precision_check.py`、`physics_check.py`，以及 `profile_variant.py concat --output /tmp/新目录1` / `profile_variant.py slice --output /tmp/新目录2`；目录须无既有检查点，两次之间保持全部输入不变。采集需要 CUDA CUPTI 库路径，与父目录报告相同。

完整 PPO 结果保存于 `benchmark.json`、`concat/` 和 `slice/`；每版包含 `profile.json`、`analysis.json`、`metadata.json`、日志、检查点和原始 GPU 轨迹。采集内核分类包含融合归属的不确定性，实际收益以未采集的预热后训练吞吐为准。
