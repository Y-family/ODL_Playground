## 先确认通信

脚本为仓库的 `scripts/collect_zp10d.py`，可复制到连接舵机的 Windows 电脑单独运行。
只依赖 Python 3 和 pyserial，不需要在这台电脑安装 BAM、MuJoCo 或 CUDA。
下面使用 Windows 的 `py` 命令；Linux 换成对应的 `python3`，端口换成 `/dev/ttyUSB0` 等。

```powershell
py -m pip install pyserial
py scripts/collect_zp10d.py ports
py scripts/collect_zp10d.py probe --port COM5 --id 0 --baud 115200 --output zp10d_probe
```

本次 Windows 已枚举到 `USB-SERIAL CH340 (COM5)`；以后按实际端口调整。
若只复制了脚本，去掉命令中的 `scripts/`。
默认 ID 为 0；如果此前改过 ID，使用实际 ID。先关闭占用同一串口的调试助手或厂商软件。
目前 WSL 内没有 `/dev/ttyUSB*` 或 `/dev/ttyACM*`，因此 Windows 直采通常更直接。

`probe` 只发送版本、模式和角度查询，不发运动或配置指令。
正常会显示 `version`、`mode`、`position_pulse_us`，并保存 `zp10d_probe/probe.json`。
工作模式 1/2 是 270°位置模式，3/4 是 180°位置模式，5–8 是马达模式，后者会被采集程序拒绝。
模式 1/2 中 P500–P2500 名义对应 270°，P1500 是名义中点，**不是回读了 1500°**。
弧度换算使用当前模式的名义角度范围，实际比例还需用物理角度检查。

如果超时，把 `probe.json` 里的错误和原始回包提供给我；先检查端口、ID、波特率及回读通路。
单总线接口需要支持接收回读的转接板，仅有 TX 的连接不够。
脚本面向透明串口/自动收发切换的单总线适配器；需要手动方向控制或私有封包的控制板需另适配。
不会通过广播修改 ID、改波特率或恢复出厂来尝试连接。

## 第一轮：6 秒小角度慢速测试

此轮使用一只独立舵机，固定外壳，输出轴有足够转动空间，先不挂负载。
使用舵机的独立电源并共地；电压参数填写**实际供电**，不从 USB 给舵机电机供电。
本次用户已明确实际7.8 V，命令填写 `--voltage 7.8`。
之前的6.6 V是仿真假设，不与本组7.8 V实物数据混用。

读回的模式、位置和接线确认正常后执行：

```powershell
py scripts/collect_zp10d.py record --port COM5 --id 0 --voltage 7.8 --profile slow --output zp10d_slow
```

围绕启动时的实际回读位置运动，偏移为 0 → +50 → −50 → 0 个 P 单位，
270°模式下为约 ±6.75°。每条指令 T1000，每段记录 1.5 秒，总长约 6 秒。
程序不盲目移动到 P1500，不改变模式、PID、偏差、ID、保护值或角度限位。
请观察是否确实缓慢往返、回读位置是否随实际运动变化。
如果回读瞬间跳到最终目标、机械动作仍在继续，应暂停后续辨识并先确认 PRAD 的反馈含义。

采集自动保存：

| 文件 | 内容 |
|---|---|
| `samples.csv` | 每次查询的时间、回包延迟、目标 P、实际 P、名义相对角度、T 时间 |
| `capture.json` | 模式/固件、填写的实际电压、测试计划、实际发送时间、原始收发字节、采样频率、退出状态 |

时间戳来自电脑单调时钟，位置时刻标为“收到回复”，同时保存查询起止，**不是编码器硬件采样时间**。
默认尝试 100 Hz，报告真实频率及最大间隔；不能把请求频率当成舵机反馈刷新率。
出现超时、异常位置或 Ctrl+C 时保留已有数据并尝试 PDST 停在当前位置；
不自动释力或在反馈失败后强行回中。停止命令无法确认时终端会报告。
相同目录已有数据会拒绝覆盖，避免丢失原始记录；不同测试条件使用各自目录。

本次 probe 已由助手经 Windows 串口执行并留档，无需重复提供。
下一步提供整个 `zp10d_slow` 目录，以及实际电压、是否安装舵盘/负载的说明。
无需手工计算速度、加速度或力矩。

## 第二轮：阶跃响应与已知负载

慢速数据确认反馈有效后，再采最大 ±100 P（270°模式约 ±13.5°）的空载阶跃：

```powershell
py scripts/collect_zp10d.py record --port COM5 --id 0 --voltage 7.8 --profile steps --amplitude 100 --output zp10d_steps
```

这组约 13 秒，从小幅到大幅、正反两个方向测试，使用 T0000。
T0000 的命令格式已由厂家 ESP32 的 `myTime = 0` 示例交叉核实，
但具体固件的插值/限速效果仍需实物数据确认。
第一轮 T1000 测到的是固件运动规划与电机的组合响应，不能将这一秒当成电机物理最短响应时间。
回读过慢时先分析数据能分辨的频段，不靠插值伪造高速响应。

BAM 的标准试验是输出轴水平、摆臂在竖直平面运动的单摆。
带载采集前需要确定摆臂/载荷安装与工作范围，并记录：

- 末端载荷总质量，包含随载荷一起运动的固定物，单位 g。
- 输出轴中心到该载荷重心的距离，单位 mm，不是摆臂总长。
- 摆臂、舵盘等其他随动件的质量与尺寸；非均匀杆不能直接套均匀杆惯量公式。
- 摆臂竖直向下时的 PRAD 数值（单摆零点）、实际电压及机械运动方向。

例如 100 g 位于 50 mm 处，摆到水平时仅该点载荷的重力矩约 0.049 N·m；
这只是单位/测量示例，尚未针对你的安装确认测试负载。
先将现有摆臂、载荷和上述测量值提供给我，再确定带载轨迹。
使用多个已知负载/惯量，并保留不同于拟合数据的验证动作；不需要堵转测最大扭矩。

## BAM 如何使用这些数据

本次核对 Rhoban/bam 提交 `e9a619d56da5236206f4de6ceec2c1ee1b497b5c`。
参考官方 [安装和采集](https://bam.readthedocs.io/en/latest/identification/acquisition.html)、
[台架](https://bam.readthedocs.io/en/latest/identification/setup.html)及
[拟合](https://bam.readthedocs.io/en/latest/identification/fitting.html)文档。
该版本需 Python 3.12；官方安装命令为克隆仓库后 `uv sync --extra identification`。
采集电脑可以只安装 pyserial，拟合留在当前 Linux 环境完成，不要求 GPU。

具体处理顺序：

1. 检查回包、采样间隔、实际位置是否有效、真实角度比例以及 T 对响应的影响。
2. 结合已知负载/惯量，把采集结果转换成 BAM 的弧度/秒/千克/米格式。
   位置在适当时间网格插值，阶跃目标按实际发送事件保持，不能把目标线性插值成不存在的慢动作。
   相对启动角并非单摆重力零点；不能把负载质量/摆长等缺项直接填零。
3. 实现并注册 ZP10D 的 BAM 执行器模型。现有上游注册表**不含 ZP10D**，
   不能直接执行 `bam.feetech.record` 或把 `--actuator` 换成未注册的 `zp10d`。
   ZP10D 例程给了 PI 设置入口，但没有当前增益的读取/标定细节；保持原设置，
   依据实测拟合等效响应，不把飞特的控制增益、齿轮参数当成 ZP10D 的值。
4. 从 M1 简单摩擦模型开始，用 BAM 优化仿真/实测位置误差，同时检查延迟、响应速度、
   参数是否卡在搜索边界。增加模型复杂度前先看独立验证动作的误差。
5. 用未参与拟合的动作和负载验证，再导出并校验 MuJoCo 参数，最后回到当前机器人运动/PPO测试。

BAM 所需原始结构包含 `mass, arm_mass, length, kp, vin, motor, trajectory, entries`；
条目中为 `timestamp, position, speed, goal_position, torque_enable` 等。
本脚本输出保留原始数据且标记 `bam_ready=false`，尚未伪造缺失的电流、转矩、内部 KP 或重力零点。
拿到数据和安装信息后，由我负责适配、转换、拟合及误差报告。
最新 BAM 的 `bam.to_mujoco` 已说明导出为常数参数属于近似；
当前项目沿原流程使用 MuJoCo 位置执行器，仍需确认导出模型能复现实测，不能只看拟合分数。

## 厂家协议交叉核对（2026-10-19）

依据 `/root/ZP10D舵机/03-源码例程` 内五份完整 ZIP 解压源码，结合此前28页手册核对：

| 项目 | 厂家例程证据 | 本脚本 |
|---|---|---|
| 串口 | ESP32 `Serial.begin(115200,SERIAL_8N1,16,17)`；STM32 8位/1停止位/无校验/无流控 | 明确设置相同参数，可用 `--baud` 指定已知实际波特率 |
| 位置 | ESP32、STM32 `#%03dP%04dT%04d!`，P500–2500，T0000–9999 ms | 相同 ASCII 格式，三位 ID、四位 P/T |
| 帧结束 | STM32 `uart3_send_str` 发到字符串结尾，不加换行；ESP32 使用 println | 发送 `!` 结束，不依赖 CR/LF；接收忽略 CR/LF |
| 查询 | ESP32/STM32 `PVER`、`PMOD`；回读例程 `PRAD` | 相同，只读 probe |
| 位置回复 | `Kibot1-JxbAR/loop.ino` 注释及解析 `#000P1500!`，ID三位、P四位 | 按完整帧/目标 ID 校验，忽略查询回显及其他 ID |
| 停止 | ESP32/STM32 `#000PDST!`，手册定义当前角停止及 `#OK!` 应答 | 相同；保存是否收到 ACK |
| 模式 | 1/2=270°，3/4=180°位置模式，5–8=马达模式 | 只允许1–4，保留当前配置 |

实物查询进一步发现旧手册未覆盖的两种回复，已兼容并保留旧格式：

```text
#000PVER!  -> #000@ ZL-ZServo_AD_CBM V2.1.16STG!\r\n   （旧格式 #000PV0.97!）
#000PMOD!  -> #000MOD1!                               （旧格式 #000PMOD1!）
#000PRAD!  -> #000P2071!
```

修复前原始记录为 `training/actuator_capture/probe/probe.json`，
修复后为 `training/actuator_capture/verified_probe/probe.json`。
修复后状态 `complete_read_only`，三条查询的回包耗时约10.26/3.77/5.50 ms；
这是单次串口往返时间，不是编码器刷新率或舵机运动延迟。
实际 ID0、115200/8N1、模式1（270°位置模式）及P2071已确认。
读取版本时明确过滤命令原文回显，避免把 PVER 误解析成版本“ER”。

资料差异也已记录：例程写 `PRTV` 电压温度查询，另有 `PPAAAIBBB` 设置 KP/KI；
旧手册与示例的波特率设置编号不一致。当前采集不使用这些配置/遥测指令。
Arduino 的 AREX 示例某些格式串误写为 `#%03dT%04dT%04d!`，部分常量漏掉 `!`；
以 ESP32、STM32 与手册一致的 P 字段/完整帧为依据，没有照搬上述错误。
STM32 示例还包含广播改 ID，回读板例程启动时会运动并释力；采集工具没有执行这些初始化。
这些文件是外部控制器示例，不是 ZP10D 内部闭环控制源码，无法据此断定内部 PI/插值的精确算法。
